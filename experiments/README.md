# Game Service 실험

Game Service(퀘스트 · XP · Outbox)가 지켜야 하는 두 가지를 실제로 돌려서 확인한 도구와 결과다.

1. **XP 는 정확히 한 번 지급된다** — 같은 이벤트가 여러 번 와도, 동시에 와도, 늦게 와도
2. **실패 하나가 전체를 멈추지 않고, 멈추면 알 수 있다** — DLT · 재처리 · 정합성 대조 · 알림 · 추적

> 이 폴더와 실험용 지연 · 실패 주입 설정(`rpgym.experiment.*`)은 이 실험 브랜치에만 있다. 설정의 기본값은 모두 "아무것도 하지 않음"이다.
> 실제 서비스 코드 변경은 develop 에 따로 머지했다.

## 돌리는 법

```powershell
# 저장소 루트에서
docker compose -f docker-compose-develop.yml up -d postgres-game kafka redis
cd experiments
powershell -ExecutionPolicy Bypass -File .\run_exp.ps1 -Exp late-events     # 실험 이름 목록은 run_exp.ps1 머리말
```

- 관측 · 장애 실험은 관측 구성(`docker-compose-observe.yml`: Prometheus, Grafana 알림, Loki, Zipkin)을 실행기가 직접 띄운다
- Slack 알림을 받으려면 저장소 루트 `.env` 에 `SLACK_WEBHOOK_URL=` 을 넣는다(`.env` 는 git 에 올리지 않는다)
- 결과는 `game-service/exp-results/<실험>_<시각>.txt`(요약 · 검증 SQL · 판정)와 같은 이름의 `.log`(앱 로그)로 남는다. 이 폴더의 `results/` 는 그 `.txt` 만 모은 사본이다
- 템플릿(`*.template.txt`)의 `__TODAY__` · `__NOW__` 는 실행 때 채워진다

## 결과 파일을 읽을 때

- 같은 실험의 회차가 여러 개면 위 표에 적은 회차가 판정에 쓴 것이다. 나머지는 설계를 바꿔 가며 실패한 회차(예: 랭킹 순서 역전이 안 생긴 세 번)이고, 실패한 이유도 남겨 두었다
- 실행기 자체의 버그로 결과 파일 일부가 틀린 회차가 있다. Outbox 강제 종료 · Kafka 3대의 game.events 세기(0 으로 나옴)는 실행기 문제였고, Outbox 강제 종료는 브로커 덤프(`Outbox_강제종료_kafka_dump.txt`)로 다시 셌다
- `_archive/` 는 2026-09 파티 동시성 실험의 이전 README 다. 그 실험은 실제 경합을 거의 만들지 못했다(겹친 파티 3개)는 것이 나중에 드러나 다시 했다
